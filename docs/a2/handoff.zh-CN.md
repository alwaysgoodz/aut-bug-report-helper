当前交付包括可运行软件、两次技术增量及真实检查记录、受控流程实验、性能原始数据、英文评价报告草稿和演示脚本。固定技术评审标签为 `a2-review-v0.1`。这仍不是经过四人团队独立审批的最终作业提交。

## 立即运行

```powershell
Set-Location -LiteralPath 'F:\COMP\Contemporary Methods in Software Engineering\bug-report-helper'
& 'D:/anaconda/python.exe' -m bugreport --db reports.db serve --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。用同一个数据库文件重启即可保留报告；换一个空文件就是另一份数据。若 8765 已占用，可改 `--port 8766`。为预览准备的进程使用单独的 `tmp/demo-preview.db`；其中四条缺陷来自虚构的 Study Planner，不是本软件未修复的真实缺陷。

全新机器按根目录 README 克隆、检出标签并运行；应用只需 Python 3.11/3.12 的标准库。浏览器自动化才需要 Node 和 Playwright。数据库不进入 Git，自动测试/性能测量创建自己的临时数据库，不清空用户报告。

## 功能与证据

- 创建与查看七字段报告，错误返回保留已填内容并聚焦可点击摘要。
- 持久化状态 Open → In progress → Resolved → Open；旧页面的过期更新被拒绝，避免无声覆盖。
- 完整度按六个非空文本字段与显式严重程度计算，0 / 86 / 100 等边界已验；只是信息存在，不代表内容正确。
- 严重程度与状态组合筛选、无匹配提示、清除筛选；键盘表单与 390px 布局已检查。
- 43 项功能层 Python/HTTP 检查通过。unittest 发现 44 项时，多出的是只在远程 Python 3.12 执行的浏览器桥接项；本地跳过是预期行为。
- 7 项浏览器测试在本机 Chrome 和远程 Chromium 均通过。远程日志明确包含 `CI_BROWSER_SUMMARY`，不是只看到了一个绿勾。
- 500 条合成数据、5 次预热、50 次单客户端完整响应请求：median 51.5742 ms，p95 77.8756 ms，满足事前 <250 ms 目标。只适用于已记录本机、热缓存、单客户端条件。

## 流程改进为什么有证据

I1 暂时关闭“错误摘要聚焦”这一行时，34 项 Python/HTTP 测试仍通过，浏览器中聚焦条件失败。I2 增加可执行浏览器断言后，同一改动在 `toBeFocused` 处被检测到；辅助脚本用 finally 恢复原字节，随后完整 7 项浏览器测试通过。

可支持的结论是“这个浏览器回归能被自动检测，并能在 CI 重复检查”。不能据此说普遍缺陷减少、团队效率提高或 100% 质量。共同比较场景 C1/C2/C3 和指标在 I2 前已有文档。A1 原定的四人产品使用评价尚未进行，不能用技术实验替代人类评价结果。

## 已处理的现实限制

本地 Playwright Chromium 下载被 CDN 中断，测试显式采用已安装 Chrome 155；CI 成功下载并使用 Chromium 156。报告分别记录环境，未把二者当成相同条件比较耗时。

GitHub OAuth 授权没有 workflow 写权限，不能更新 Actions 工作流。共享工作流保持原样，已有的 Python 3.12 检查通过条件桥接执行浏览器套件；未改你的登录、令牌或账户权限。该做法会耦合检查层，报告说明独立 browser job 是可考虑的后续结构。

A2 明确要求 Week 2 内两轮，已将 A1 暂定的每轮五个工作日调整为每轮两个工作日，加一天最终准备；原 A1 快照保留。当前实际开发是一次 AI 辅助准备会话中的两个技术增量，不冒充已经完成四人、两轮日程。

## 需要团队完成的具体动作

1. 提供四位成员姓名、学号和 GitHub 用户名，确认分工和投入时间。
2. 邀请真实成员与评阅者，验证私有 Issues/PR/Actions 均可访问。
3. 非作者实际检出 PR，独立运行检查并留下有内容的审查，作者回应；按依赖顺序审查 #7 → #8 → #10 后再合并。
4. 记录真实团队回顾，执行原定产品评价或在主文有依据地说明遗漏；不得填造问卷、时间、参与者或修复数据。
5. 每位学生填写个人贡献陈述，链接具体决定、实现、审查、测试或评价及结果；不能只用 commit 数。
6. 修改报告身份和实证内容后重新计数、生成 PDF 并逐页检查；按 Canvas 确认要求和截止时间，由团队确定经过审批的最终提交 SHA/tag。

当前标签、源码、日志与报告已经为这些步骤提供可直接审查的材料。具体链接见 evidence-index.md 和 demo-runbook.md。
