## 运行

在仓库根目录执行（Windows 可将 python 换为已验证的 D:/anaconda/python.exe）：

```powershell
python -m tools.peer_study serve --data-dir study-data --port 8766
```

打开 http://127.0.0.1:8766 。工具只绑定本机；四人可依次在同一台电脑操作，不需要云部署或登录。不要把 8766 暴露到公网。Ctrl+C 停止。报告、同意和时间只在本地 `study-data`，该目录不进 Git。

练习必须使用独立目录，不能用正式目录：

```powershell
python -m tools.peer_study serve --data-dir tmp/peer-study-pilot --port 8767 --test-only
```

练习结果即使满 4 对，也不会被标记为真实研究完成。正式试验不要由自动化点击同意或填写报告；参与者自行操作。

## 独立复现与七项语义完整度

收完报告后，评审者仅打开首页的 Independent reviewer。报告随机键排序，隐藏分组和时间。先依据报告在 A/B 中尝试复现，再逐项标“存在/缺失”，每项必须明确选。不能按“表单里出现了标签”就判为有信息。

| 元素 | 计 1 的统一标准 |
| --- | --- |
| Title | 有可辨认的问题摘要，不只是“有 bug” |
| Description | 说明发生问题的任务/上下文 |
| Steps | 有可执行操作、触发路径或足以定位的动作 |
| Expected | 明确应该出现什么 |
| Actual | 明确实际出现什么，与期望可区分 |
| Environment | 能识别模拟应用/版本及使用环境的信息 |
| Severity | 明确严重程度或使用影响；不以修辞强度代替内容 |

本研究两任务均预定七项适用，得分 = 100 × 存在项 / 7。自由文本按语义编码，不能要求它有标签。该人工结果与产品的自动“非空字段分数”不同；两者不能混用。

评审者填写 R01 等匿名码，确认不是作者并进行了实际复现，记录 reproduced / needs clarification / not reproduced 以及真实澄清次数。只有 reproduced 且澄清 0 次，才计“独立复现成功”。评分提交后锁定，发现录入错误应在分析说明中记录，不能静默改原始结果。

## 导出与解释

```powershell
python -m tools.peer_study export --data-dir study-data --output study-export
```

得到 `raw-study.json`、`summary.json`、`paired-results.csv`。只读导出可在服务器运行时使用。只有两次均完成、两次均被真实评分、无重做/中断的参与者进入配对比较。不会用平均值填补缺失。比较引导减自由文本的时间差、完整度百分点差和独立复现次数；汇总给中位数与分母，不做显著性检验或普遍效果声明。

先核对原始记录，再将合适的匿名结果纳入报告；不要把练习导出提交为人类评价。保留版本、顺序、排除项、帮助、中断、便利样本/熟悉程度和条件可识别等局限。完成四对只表示该小研究的数据齐全，不证明方法普遍有效。

自愿撤回：先停止服务器，再运行 `python -m tools.peer_study withdraw --data-dir study-data --participant P01`。对应报告、引导数据库内容和评分会删除，仅保留匿名撤回事件；不要重复使用该参与者码。
