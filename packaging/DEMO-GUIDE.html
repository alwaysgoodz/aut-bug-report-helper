快速启动操作顺序四人讲解彩排检查故障处理

三步开始

  1. 完整解压整个文件夹到桌面。不要只复制启动脚本或单独移动 runtime。
  2. 双击 StartDemo.cmd。浏览器会打开本机地址；保持启动窗口开启。没有自动打开时，复制窗口显示的地址。
  3. 首次启动有 4 条虚构缺陷；再次启动保留你的演示报告。结束时在启动窗口按 Ctrl+C。

运行不需要安装 Python、Node.js、pip 或联网。数据只在当前文件夹的 demo-data 中。这个包用于本机演示；四同伴评价工具和真实研究数据不在便携包中。

操作顺序 · 约 6 分钟

  1. 总览。展示列表里的严重程度、处理状态和完整度。四条初始报告来自虚构的 Study Planner 案例。
  2. 错误恢复。打开 New report，只填写下方样例的两条复现步骤，点击 Create report。页面会聚焦错误摘要，提示补填 Title 和 Severity，原步骤仍在。
  3. 先保存一份有用的报告。填入样例标题，将 Severity 设为 High。此时三个字段齐全，评分为 43%。点击 Create report，在详情页确认已保存。
  4. 补填同一条报告。点击 Add environment，输入样例里的 Environment，评分升到 57%。点击 Save changes。再打开 Edit report，填入 Description 和 Expected behaviour，显示 86%。填入 Actual behaviour 后达到 100%，再次保存。完整度衡量有多少字段已提供信息。
  5. 状态与筛选。依次选择 In progress、Resolved、Open，每次都点 Update status。返回列表，设置 Severity 为 High、Status 为 Open，点击 Apply filters。确认刚才的报告仍在结果中，再点 Clear。
  6. 分享与验证。重新打开报告，点 Download report，展示文件中的七个字段和当前状态。也可点 Copy report。最后展示包内验证摘要和截图。

可直接输入的虚构样例

Title: Task remains visible after marking it complete
Description: In the fictional Study Planner, completed work remains in the Active view.
Steps to reproduce:
1. Open the Active task list.
2. Mark "Prepare tutorial notes" as complete.
Expected behaviour: The completed task disappears from Active.
Actual behaviour: The task remains in the Active list until the page is refreshed.
Environment: Study Planner demo 1.0 / Chrome / Windows 11
Severity: High

若剪贴板权限不可用，界面会明确提示使用 Download report。下载文件包含当前已保存的状态与七个字段。

演示前检查

  • 把 ZIP 复制到演示电脑，在新文件夹解压，双击 CheckDemo.cmd，确认自检成功。
  • 关闭网络后再启动并完整走一遍操作顺序。浏览器缩放先用 100%，投影时再按需调到 110% 或 125%。
  • 做一次保存 → 停止 → 再启动 → 读取原报告，确认演示电脑可以写入数据。
  • 需要干净开场时，先停止程序，再运行 ResetDemo.cmd，输入 RESET；查看备份和重新生成的四条示例。
  • 准备一个浏览器标签展示系统、一个标签打开本手册、另备验证摘要和保存的截图。
  • 每人计时演练 2.5 分钟，并为自己的真实判断、代码或评审准备可核对的链接。

现场应急

从 1.0.0 升级时，先关掉旧启动窗口。把旧包 demo-data 中的 demo-reports.db 复制到新包的 demo-data 文件夹，再启动新版。旧包可作为备份。

现象处理
浏览器未自动打开启动窗口仍在时，复制它显示的 http://127.0.0.1:端口/ 地址。端口可能不是 8765。
重复双击启动同一数据目录会复用正在运行的工作区，不会启动两个写入进程。
端口被其他应用占用启动器自动绑定系统分配的其他端口。使用启动窗口里的实际地址。
提示表单过期 / 页面无法连接确认启动窗口运行；重启后刷新表单再提交。已保存的数据仍在。
重置被拒绝先在原启动窗口按 Ctrl+C；ResetDemo.cmd 不会重置正在运行的数据。
启动失败 / 文件缺失完整重新解压到可写目录，再运行 CheckDemo.cmd。日志在 demo-data/server.log。
演示电脑故障使用验证摘要和截图说明已验证行为，并明确当前无法现场运行，不能把截图说成实时操作。
包内 BUILD-INFO.json 记录源码 commit、文件 SHA-256 和运行环境来源。原始 Python 许可在 runtime/LICENSE.txt。此手册不代替作业要求的真实团队活动、评审与产品评价。
